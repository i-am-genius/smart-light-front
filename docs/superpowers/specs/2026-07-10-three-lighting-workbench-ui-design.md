# Three 场景沉浸式灯光编排工作台 UI 设计

## 目标

将现有 Three.js 精品服装店灯光场景从“工具条 + 3D 画布”升级为以场景为核心的沉浸式灯光编排工作台。用户应能快速判断当前区域和视角模式，选中射灯后直接完成移动、删除等上下文操作，同时保持场景主体清晰、移动端可触控。

本次只调整 `ThreeLightingLayout.vue` 的模板结构、展示型派生状态和 scoped CSS。设备数据、灯位绑定、分区切换、拖拽、排序、删除、均匀排列、相机预设、本地持久化和组件事件保持不变。

## 现状与设计判断

当前界面存在四个主要问题：

- 分区、添加、移动、删除和均匀排列均以相近视觉权重出现，主操作与上下文操作没有分层。
- 选中状态主要依赖文字提示，场景中的选中射灯与外部控制之间缺少明确关联。
- 单个“调节射灯视角/展示视角”按钮描述下一步动作，不够直观地表达当前模式。
- 移动端只缩短了画布高度，控制栏仍按桌面结构自然换行，触控目标和遮挡风险没有被专门处理。

因此采用方案 A“沉浸式灯光编排工作台”：控制进入视口悬浮层，常驻操作与选中后操作分开，现有系统蓝继续代表可操作状态，精品店暖金色只作为场景身份点缀。

## 信息架构

界面分为三层，全部位于 `.three-viewport-wrap` 内：

1. **场景工具栏**：位于视口顶部，提供区域切换、灯位数量、添加灯位、布局操作和视角模式。
2. **Three.js 场景**：保持现有画布、射灯选中、拖拽、相机和渲染逻辑，是页面的视觉主体。
3. **上下文操作台**：位于视口底部。未选中时显示操作引导；选中后显示灯位身份及左移、右移、删除操作。

桌面结构示意：

```text
┌────────────────────────────────────────────────────┐
│ [‹] 默认展示区 1/1 [›]  · 3 个灯位   + 添加灯位   │
│                         布局操作  [展示 | 调节]    │
│                                                    │
│                    Three.js 场景                   │
│                                                    │
│ 拖动射灯调整焦点   [已选：射灯 02] [←][→][删除]   │
└────────────────────────────────────────────────────┘
```

## 场景工具栏

### 区域信息

- 保留当前左右区域切换按钮及禁用条件。
- 区域名称与 `当前序号 / 总数` 合并成一个紧凑信息组。
- 增加由现有 `layoutState.lamps.length` 派生的灯位数量文本，不增加接口或持久化字段。
- 区域名称超长时单行省略，但保留完整 `title`，便于鼠标用户查看。

### 灯位与布局操作

- “添加灯位”是工具栏唯一的主要按钮，继续调用 `addManualSlot`。
- “均匀排列”作为次要的全局布局操作，继续使用当前禁用条件和 `handleArrangeSlotsEvenly`。
- 左移、右移、删除不再常驻顶部，全部移入选中后的上下文操作台。
- 本轮不新增撤销、保存、确认弹窗或更多菜单，避免改变现有操作模型。

### 视角模式

- 将当前单按钮改为“展示 / 调节”双状态分段控件。
- 当前激活项必须具有实色或高对比选中态，另一项为未选中态；用户看到的是当前模式，不再需要解读下一步按钮文案。
- 两个分段仍由同一个 `toggleCameraView` 入口驱动：点击未激活项时切换，点击已激活项时不执行操作；不新增相机模式。
- 两个分段都使用 `aria-pressed` 表达当前选中态，并保留键盘焦点样式。

## 上下文操作台

### 未选中状态

- 左下显示“点击射灯后可编辑位置”。
- 辅助提示“拖动射灯调整陈列焦点”保持低视觉权重。
- 不显示任何不可用的移动或删除按钮，减少无效控件噪声。

### 已选中状态

- 展示 `selectedSlotLabel` 对应的灯位名称。
- 可从现有选中灯位数据派生时，显示在线、离线或手动灯位状态；无法可靠判断时只显示名称，不制造未知状态。
- 左移与右移继续使用 `canMoveSelectedLeft`、`canMoveSelectedRight`。
- 删除继续使用 `canDeleteSelectedSlot` 和 `deleteSlotTitle`，危险操作使用红色并与移动操作留出分隔。
- 禁用按钮除降低透明度外，继续通过 `title` 给出具体原因。
- 上下文操作台的蓝色选中标识与 3D 场景现有 selection ring 使用同一强调色，建立灯具与控件之间的视觉对应。

### 拖拽状态

- 不改变任何射灯或轨道拖拽命中逻辑。
- 拖拽期间只允许增加轻量的视觉状态，例如提高上下文操作台选中标识亮度；不增加阻断式提示。
- `pointer-events` 必须只作用于真实控件，提示文字和装饰层保持不拦截 Three.js 画布。

## 视觉系统

### 颜色

- 主操作蓝：`#2563EB`
- 深色文字：`#0F172A`
- 次级文字：`#64748B`
- 中性画布：`#F8FAFC`
- 精品店点缀金：`#C8A56C`
- 危险操作：`#DC2626`

工具层采用中性半透明玻璃背景、细边框和克制阴影。暖金只用于细分隔线、灯轨式状态线或微小场景身份标识，不用于主要按钮，避免与应用现有蓝色交互语言冲突。

### 字体与尺寸

- 延续项目现有中文系统字体，不新增字体资源。
- 区域名称和选中灯位名称为 13–14px、700–800 字重。
- 状态和辅助提示为 11–12px、600–700 字重。
- 桌面按钮视觉高度不低于 34px；移动端触控区域不低于 44 × 44px。

### 标志性元素

工具栏使用一条细的“灯轨状态线”连接区域、灯位数量和当前选中状态，呼应场景中的实体轨道。该元素只承担分组与状态关联作用，不添加无意义装饰或循环动画。

## 响应式布局

### 桌面端：大于 1180px

- 工具栏在视口顶部单行悬浮。
- 区域信息靠左，灯位与视角操作靠右。
- 上下文操作台位于底部，不遮挡主要射灯或服装陈列。
- 视口保持当前 430px 高度规则。

### 平板端：769–1180px

- 工具栏允许分成两组或两行，但区域信息与视角模式不得拆散。
- 上下文操作台可占据底部较宽区域，按钮仍保持完整文字或清晰可访问标签。
- 不通过缩小 Three.js 场景主体来容纳工具栏。

### 移动端：不大于 768px

- 视口继续保持当前 360px 高度。
- 顶部仅常驻区域切换和视角模式；添加与均匀排列进入紧凑的第二行操作区。
- 选中后，上下文操作台固定在视口底部并可自然横向排列或换行，不使用超出视口的菜单。
- 所有控件至少提供 44px 触控区域，文字省略不能移除可访问名称。
- 场景提示在上下文操作台出现时降低或隐藏，避免视觉重叠。

## 夜间模式与无障碍

- 夜间模式沿用应用现有 `.app-container.night-mode` 入口，使用深色玻璃背景和浅色文字；蓝色强调色与危险色保持足够对比。
- 所有按钮保留清晰的 `:focus-visible` 轮廓。
- 图标按钮必须具有 `aria-label` 或可见文字，不能仅依赖方向箭头表达含义。
- 禁用状态不能只通过颜色表达；保留 `disabled` 属性和解释性 `title`。
- `prefers-reduced-motion: reduce` 下关闭位移和装饰性过渡。
- 装饰型场景提示使用 `aria-hidden="true"`；状态与操作文本必须对辅助技术可读。

## 状态与数据流

UI 只消费现有响应式状态，不建立第二套状态源：

- 区域信息来自 `activeZone`、`activeZoneIndex` 和 `zoneCount`。
- 灯位数量来自 `layoutState.lamps.length`。
- 当前灯位来自 `selectedSlot`、`selectedSlotId` 和 `selectedSlotLabel`。
- 移动与删除可用性来自现有 `canMoveSelectedLeft`、`canMoveSelectedRight`、`canDeleteSelectedSlot` 和 `deleteSlotTitle`。
- 视角选中态来自 `cameraViewMode`。

模板重排后的按钮继续调用现有处理函数。任何新增展示型 computed 只能组合现有数据，不写入设备、灯位或持久化结构。

## 代码边界

- 主要改动限定在 `src/components/device/ThreeLightingLayout.vue` 的 template 和 scoped CSS。
- 可以增加少量纯展示 computed 或可访问性属性，但不修改灯位算法、Three.js 对象、事件监听、存储键或组件 props/emits。
- 本轮不拆分新子组件。虽然现有文件较大，但拆分会扩大状态传递和生命周期改动范围，不服务于本次 UI 目标。
- 不修改 `SmartLightDashboard.vue`；悬浮工具层必须在 `ThreeLightingLayout.vue` 当前容器边界内完成布局。

## 验证与验收

### 自动验证

- 扩展现有 Three 场景源码契约测试，确认区域切换、添加、移动、删除、均匀排列和视角切换的处理入口仍存在。
- 增加 UI 结构断言，保护场景工具栏、双状态视角控件、未选中提示和选中上下文操作台。
- 运行现有 Three 场景测试以及完整 TypeScript/Vite 生产构建。

### 人工验收

- 未选中射灯时，用户能在 3 秒内识别当前区域、灯位数量、视角模式和添加入口。
- 选中射灯后，左移、右移和删除操作只在上下文操作台出现，场景中的选中射灯与操作台视觉关联明确。
- 展示与调节模式的当前状态无需点击即可判断。
- 1366px 桌面、约 1024px 平板和 390px 移动端均无横向溢出，工具层不遮挡核心射灯。
- 鼠标、触控和键盘焦点状态均可辨识；夜间模式对比度清晰；减少动态效果偏好生效。
- 原有射灯拖拽、区域切换、灯位排序、删除限制、均匀排列、相机切换和刷新后的布局恢复行为保持不变。

## 范围外

- 不增加亮度、色温或灯效控制，这些继续由现有灯效面板负责。
- 不新增后端接口、设备字段、网络请求或持久化数据。
- 不重做 Three.js 精品店场景材质、模型、灯光或相机参数。
- 不增加撤销、批量选择、保存按钮、快捷键系统或复杂属性检查器。
